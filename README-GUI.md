# MonkeyAutoTest GUI 使用手册

本文档仅说明 GUI 界面的功能与操作方法。项目概览、安装与命令行入口请查看 `README.md`。

## 1. 启动方式

在项目根目录执行：

```bash
python gui_main.py
```

首次建议先确认：

- `adb devices` 能看到目标设备
- 已准备可安装的 APK
- `conf/project.json` 中存在可选项目版本

## 2. 主界面功能卡片

主界面以卡片组织，核心区域如下：

- `📋 项目配置`：选择项目版本、目标设备、APK 路径，刷新设备列表
- `⚡ 测试操作`：启动/停止测试，打开测试配置窗口，查看报告
- `📱 设备状态`：展示连接状态、设备信息与当前应用信息
- `📊 测试进度`：显示测试阶段、进度与运行状态
- `📝 实时日志`：查看运行日志，支持滚动查看与保存
- `🧪 Mock Server`（在操作区相关入口）：用于异常恢复等场景联动

## 3. 典型操作流程

1. 在 `项目配置` 中选择版本、设备 SN、APK。
2. 点击“刷新设备列表”，确认目标设备在线。
3. 点击“打开测试配置窗口”，配置模块与参数。
4. 返回主界面，点击“开始测试”。
5. 在 `测试进度` 与 `实时日志` 中观察执行状态。
6. 结束后通过“查看测试报告”打开报告。

## 4. 测试配置窗口说明

测试配置窗口是 GUI 的核心配置入口，主要包含以下卡片。

### 4.1 `🧩 自定义模块组合`

- 支持预设组合（例如：完整套件、仅 Monkey、仅性能等）
- 支持手动勾选模块
- 当前支持模块：
  - `Monkey 模式压力测试`
  - `异常恢复测试`
  - `完整性能测试`
  - `仅响应性能测试`
  - `广播模式压力测试`
  - `TTS 模式压力测试`

### 4.2 `🛡️ 参数设置`

- `测试方案`：快速/标准/深度/长期等时长预设
- `网络模拟方法`：
  - `root`
  - `pc_proxy`
  - `wifi_control`
  - `app_simulation`
- `多设备SN(空格分隔)`：并行多设备执行入口

### 4.3 `📡 广播 / 🔊 TTS 配置`

广播与 TTS 共用区域，常见字段：

- 广播：
  - `广播Hints(每行一条)`
  - `Hints文件路径(可选)`
- TTS：
  - `TTS 文本(每行一条)`
  - `TTS 文本文件路径(可选)`
  - `结束词(可选)`
  - `唤醒词(可选)`
  - `唤醒后等待(秒)`
  - `TTS 间隔(秒)`
  - `TTS 音量(%)`
- 响应监控（广播/TTS 共用）：
  - `最大等待出现(秒)`
  - `检测间隔(秒)`
  - `最大等待消失(秒)`
  - `连续 ANR/无响应次数阈值`

### 4.4 `🧾 App Log 精准采集`

用于目标应用日志的差异化采集与实时落盘，关键字段：

- 启用开关：`启用 App Log 精准采集`
- 目标范围：
  - `额外包名(逗号分隔)`
  - `进程名(逗号分隔)`
  - `包名-进程映射`
- 过滤规则：
  - `级别过滤`
  - `包含TAG(逗号)` / `排除TAG(逗号)`
  - `包含关键词(逗号)` / `排除关键词(逗号)`
- 输出与性能：
  - `输出子目录`
  - `单文件上限(MB)`
  - `备份份数`
  - `刷新PID秒`
  - `批量行数`
  - `落盘周期(ms)`

### 4.5 `⚙️ 测试选项`

- `建立性能基线`
- `与基线对比`
- `禁用Mock Server`
- `禁用网络代理`
- `直接使用Fallback事件注入`

### 4.6 `🔲 Monkey 遮罩区域（百分比 0.0 - 100.0）`

用于控制 Monkey 可点击区域，避免触发状态栏、导航栏等高误触区。

- 参数：
  - `上边缘`
  - `下边缘`
  - `左边缘`
  - `右边缘`
- 辅助按钮：
  - `生成当前遮罩预览`
  - `打开最近遮罩图`

## 5. Monkey 遮罩配置详细步骤

1. 打开“测试配置窗口”。
2. 找到 `🔲 Monkey 遮罩区域` 卡片。
3. 输入四个边缘百分比（范围 `0.0-100.0`）。
4. 点击“生成当前遮罩预览”检查覆盖效果。
5. 如遮罩过大/过小，调整后重新预览。

建议：

- 初次可从 `上/下 5-10`、`左/右 0-5` 开始。
- 对有手势条或系统悬浮区的设备，适当增大对应边缘。

## 6. GUI 参数作用速查

- `测试方案`：控制整体测试时长预设
- `网络模拟方法`：决定异常恢复/网络相关场景执行方式
- `广播Hints/TTS文本`：压测输入语料来源
- `唤醒词/结束词`：TTS 播放前后附加语句
- `TTS 间隔`：两条语料之间的间隔周期
- `TTS 音量`：TTS 引擎输出音量比例
- `响应监控参数`：影响超时判定与 ANR 统计敏感度
- `App Log 参数`：影响采集范围、过滤精度与磁盘占用

## 7. 设备控制（投屏/录屏）

设备控制页签支持两类独立会话：

- 投屏（Mirror）：用于实时展示设备画面，并可进行触控交互
- 录屏（Record）：用于生成文件（视频 + 系统音 + 环境/麦克风声音 + app.log），且与投屏开始/停止时间解耦

### 7.1 投屏（Mirror）

- 点击 `开始投屏`：启动一个独立的 `scrcpy` 投屏窗口
- 点击 `停止投屏`：仅停止本会话启动的 `scrcpy` 进程树（不会影响稳定性测试等其它 `adb` 使用）

### 7.2 录屏（Record）

- 点击 `开始录制`：启动双路 `scrcpy`（画面+系统音 + 麦克风/环境音），麦克风来源可在录屏卡片中切换（设备麦克风 / 电脑麦克风(dshow)），同时启动精准 `app.log` 采集（基于 PID/级别/TAG/关键词过滤）
- 点击 `停止录制并合成`：先结束两个 `scrcpy`，等待一段时间确保日志落盘；然后从本次 session 的 `app.log` 中按“开始/结束时间窗”高效截取日志，生成最终日志，再调用 `ffmpeg` 混音并封装生成最终 MP4
- 输出目录与精准 `app.log` 同目录：`<records_dir>/<device_sn>/<YYYYMMDD_HHMMSS>/`（其中 `YYYYMMDD_HHMMSS` 为本次录制开始时间）
- 录屏卡片里的“录音麦克风”用于选择音频来源：
  - 勾选：使用设备端麦克风（scrcpy）
  - 不勾选：使用电脑端 dshow（PC端环境声），并跳过设备端 mic；此时才需要在下方选择 dshow 音频源设备

命名规则（以 `record_basename` 为前缀）：

- 临时前缀：`<record_basename>_<start_YYYYMMDD_HHMMSS>`
- 临时视频：`<temp_prefix>_video_tmp.mkv`
- 临时麦克风音频：`<temp_prefix>_mic_tmp.*`（会扫描最新且非空的临时音频参与混音）
- 临时 logcat 捕获：`logcat.log`（录制结束后按同一时间窗切片输出最终文件）
- 最终合成 MP4：`<record_basename>_<start_HHMMSS>-<end_HHMMSS>_final.mp4`
- 最终日志：`<record_basename>_<start_HHMMSS>-<end_HHMMSS>_final_app.log`
- 最终 logcat 切片：`<record_basename>_<start_HHMMSS>-<end_HHMMSS>_final_logcat.log`
- 精准采集文件：`app.log`（仅用于切片；若勾选 `停止录制后删除临时文件`，会在合成后删除）

### 7.3 日志抓取与注意事项

- 录屏日志来自两步：
- 先用精准 `app.log` 采集写入本次 session 的 `app.log`（不再使用全量 `adb logcat` 抓取）
- 停止录制后，从本次 `app.log` 按“开始/结束时间戳”截取对应时间窗，写出最终 `<record_basename>_<start_HHMMSS>-<end_HHMMSS>_final_app.log`
- 同步写入全量 `logcat.log`，停止录制后按同一时间窗切片，写出最终 `<record_basename>_<start_HHMMSS>-<end_HHMMSS>_final_logcat.log`
- 可选项：`开始录制前清空 logcat`（默认关闭）。该操作会清空设备 logcat 缓冲区，可能影响并行稳定性采集，建议仅在需要“从零开始对齐时间戳”时开启

## 9. 常见问题

- 设备显示离线：先执行 `adb kill-server`、`adb start-server` 再刷新
- 点击开始后无执行：检查模块勾选、APK 路径与设备 SN
- 日志过大：优先收紧 `App Log` 的包名/进程/TAG/关键词过滤
- TTS 声音偏小：提高 `TTS 音量(%)`，并同步调高系统/耳机音量
